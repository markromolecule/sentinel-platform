## 3.4 SYSTEM ARCHITECTURE

This section presents the architectural design and structural blueprint of the Sentinel platform, detailing the engineering principles, communication protocols, and subsystem relationships established during its development.

The system architecture was formulated to address the dual challenges of high-concurrency remote proctoring and student data privacy. Rather than relying on bandwidth-intensive centralized cloud streaming, the platform was structured around a decoupled multi-tier architecture combining client-side edge computing, perimeter network security, containerized microservices, asynchronous message queues, and managed relational persistence.

The system diagram maps the principal application, service, and data components (see Figure 1). The diagram visualizes the flow of data across five primary clusters: institutional Users accessing dedicated Client Applications, the centralized Hono API processing inbound REST requests, the Data and Job Queue managing persistence and asynchronous workers, the Supabase Platform providing authentication, file storage, and real-time coordination, and External Services facilitating generative AI processing and on-demand live media streaming.

### Web Application Modules

In this section, the web tier is decomposed into its core functional modules. The web application ecosystem spans three specialized Next.js applications: sentinel-web (serving students taking exams and instructors authoring assessments or supervising live sessions), sentinel-core (serving institutional administrators managing academic structures and student whitelists), and sentinel-support (serving system operators managing baseline rubrics, global telemetry, and audit logs). Table X outlines the technical classification, specialized features, underlying technologies, and operational implementations of the web application modules.

#### Table X. Web Application Architectural Modules and Implementation of the Sentinel

| Classification | Specialized Feature | Technology | Technical Description & Implementation |
| :--- | :--- | :--- | :--- |
| **Identity & Access Management** | Role-Based Access Control & Bot Defense | Supabase GoTrue, Cloudflare Turnstile, Next.js Middleware | Authenticates credentials via Supabase GoTrue, injecting role claims into tamper-evident JWT session cookies. Integrates Cloudflare Turnstile CAPTCHA on login and registration gateways to block automated brute-force attacks. Enforces strict client and server route guards isolating Student, Instructor, Institutional Admin, and Technical Support domains. |
| **Institutional Governance** | Academic Hierarchy & Whitelist Provisioning | Next.js (sentinel-core), Prisma ORM, Kysely, Zod | Structures multi-tenant academic hierarchies including campuses, colleges, departments, terms, and physical room capacity definitions. Implements bulk CSV ingestion algorithms to validate institutional student ID numbers against registration claims, preventing unauthorized onboarding. Manages degree cataloging, class section generation, and faculty roster assignments. |
| **Assessment Authoring** | Two-Way Table of Specifications (TOS) & Item Banking | Next.js (sentinel-web), React Hook Form, TanStack Query, @sentinel/shared | Provides a dynamic two-way TOS matrix balancing assessment question counts across Bloom's Taxonomy cognitive domains (Remembering, Understanding, Applying, Analyzing, Evaluating, Creating). Maintains categorized question repositories supporting multiple-choice, identification, and rubric-evaluated essay items. Tracks question exposure frequency across exam iterations, automatically retiring items exceeding defined exposure thresholds (maximum 3 assessments). |
| **Generative AI Engine** | Automated Question & Rubric Generation | Google Gemini 1.5 Pro, Vertex AI SDK, Redis, BullMQ | Ingests syllabus documents, curriculum outlines, and topic context to synthesize contextual assessment questions aligned with target difficulty levels. Dispatches generation payloads to Google Gemini through asynchronous BullMQ worker queues to prevent HTTP timeout bottlenecks. Validates synthesized model outputs against strict Zod JSON schemas prior to staging in the instructor draft console. |
| **Real-Time Proctoring** | Digital Waiting Lobby & Live Anomaly Console | Supabase Realtime, LiveKit SFU (WebRTC), Lucide React | Manages candidate admission via a digital staging lobby listening to WebSocket broadcast events. Renders a live candidate monitoring grid displaying real-time anomaly badges for gaze deviation, candidate absence, background speech, and browser tab blur. Establishes on-demand WebRTC video streaming via LiveKit SFU only when high-frequency anomalies require visual confirmation, conserving cloud egress bandwidth. |
| **Evaluation & Analytics** | Automated Scoring, Rubric Grading & PDF Audit | PDFKit Engine, Supabase Storage, Prisma Transactions, Tailwind CSS | Executes instantaneous automated scoring for objective question items upon submission. Provides instructors with an ergonomic rubric grading console locked to the immutable criteria active at exam publication time, supplemented by Gemini AI essay evaluation suggestions. Compiles comprehensive PDF Attempt Audit Reports detailing chronological incident logs, forensic WebP snapshot evidence, and empirical item difficulty (P-value) analytics. |
| **Platform Operations** | Global Baseline Governance & Infrastructure Health | Next.js (sentinel-support), BullMQ Dashboard, Supabase Admin API | Configures system-wide default rubric templates, audit report layouts, and proctoring sensitivity thresholds applied across institutional tenants. Provides technical support operators with centralized access to contested proctoring logs, snapshot evidence, and anomaly false-positive recalibration. Monitors real-time API latency, Supabase database connection pooling, LiveKit SFU media packet loss, and Redis queue throughput. |

As outlined in Table X, the web application modules operate as an integrated platform. By decoupling user authentication and authorization into a shared package layer (`@sentinel/shared` and `@sentinel/hooks`), all three web clients maintain consistent access enforcement while communicating with the Hono REST backend. Assessment creation is rigorously constrained by pedagogical rules via the Table of Specifications grid, and live examination supervision utilizes on-demand WebRTC media channels, preventing server bandwidth exhaustion while ensuring immediate intervention capabilities for proctors.

### Mobile Application Modules

The mobile application ecosystem (`sentinel-mobile`) is developed using the Expo and React Native cross-platform frameworks, tailored exclusively for students taking digital examinations on smartphone devices. Because mobile environments present unique operating challenges—including variable network reliability, restricted device memory, and localized cheating vectors such as floating messaging windows or split-screen multitasking—the mobile architecture incorporates dedicated kiosk locking, local offline caching, and client-side Edge AI inference. Table X outlines the specialized technical features and implementations of the mobile application modules.

#### Table X. Mobile Application Architectural Modules and Implementation of the Sentinel

| Classification | Specialized Feature | Technology | Technical Description & Implementation |
| :--- | :--- | :--- | :--- |
| **Mobile Security** | Hardware-Backed Auth & SecureStore Persistence | Expo SecureStore, Supabase Auth, TypeScript Guards, Android KeyStore | Authenticates student accounts against Supabase Auth, validating student identity against institutional whitelists. Stores encrypted JWT access and refresh tokens inside the Android KeyStore and iOS Keychain via Expo SecureStore, preventing token extraction from rooted devices. Enforces client-side role guards that terminate execution if non-student credentials are used. |
| **Academic Lifecycle** | Academic Roster & Assessment Calendar | React Native Paper, TanStack Query, Date-fns, Vector Icons | Synchronizes student course enrollments, subject descriptions, and assigned instructor profiles from the central database. Categorizes examinations into Upcoming, Active, and Completed views, featuring real-time synchronized start-countdown timers. Renders an integrated monthly and weekly calendar detailing assessment schedules and institutional deadlines. |
| **Pre-Exam Verification** | Hardware Diagnostics & Neutral Calibration | Expo Camera, Expo Audio, MediaPipe Tasks Vision, Supabase Realtime | Conducts automated pre-exam sanity checks on front-facing camera availability, microphone input levels, and battery percentage (>20%). Executes a 5-frame neutral baseline calibration measuring the student's Eye Aspect Ratio (EAR) and neutral iris center coordinates. Places the candidate into a synchronized digital waiting room, listening to Supabase Realtime broadcast channels for instructor admission. |
| **Kiosk Lockdown** | Native OS Screen Blocker & Focus Guard | expo-screen-capture, React Native AppState, Custom Native Modules | Activates operating-system flags (FLAG_SECURE on Android) via `expo-screen-capture` to completely black out screenshots and screen recordings. Monitors native OS lifecycle transitions; leaving the application or opening split-screen multitasking triggers immediate security warnings and incident telemetry. Renders questions with auto-resizing input fields and responsive navigation drawers. |
| **Offline Resilience** | Local Answer Buffering & Delta Synchronization | @react-native-async-storage, NetInfo Network Monitor, TanStack Mutations | Persists student question responses instantaneously to device-level local storage (AsyncStorage) upon every keystroke or selection. Dispatches batched response deltas to the Hono API every 15 seconds, handling network degradation without interrupting candidate test execution. Implements exponential backoff retry algorithms that guarantee zero answer data loss if internet connectivity drops during an active attempt. |
| **Edge AI Telemetry** | On-Device Gaze Tracking & Forensic Snapshotting | MediaPipe Tasks Vision, TensorFlow.js, YAMNet Model, Supabase Storage | Runs lightweight MediaPipe Face Mesh inference at 500ms intervals, detecting lateral eye gaze deviation and candidate absence. Executes a headless TensorFlow.js YAMNet audio classifier in a background worker, identifying whispering, multi-speaker presence, or ambient speech anomalies. Captures compressed WebP forensic image frames precisely when anomalous events occur, uploading them to Supabase Storage as immutable evidence. |
| **Live Inspection** | On-Demand WebRTC Video Streaming | livekit-client, react-native-webrtc, WebSocket Engine, Expo KeepAwake | Maintains a dormant WebRTC media engine that activates only when the proctor requests a live inspection feed from the instructor console. Streams low-latency H.264 video and Opus audio to the LiveKit Selective Forwarding Unit (SFU) at dynamic resolutions to match cellular bandwidth. Receives real-time proctor warning banners, chat notices, and audio broadcasts directly within the active exam overlay. |
| **Post-Exam Lifecycle** | Hard Timeout Submission & Candidate Feedback | sentinel-mobile, Hono Exam Routes, Prisma Schema, React Native Feedback | Enforces strict time limits, automatically packaging and transmitting all buffered answers when the exam duration reaches zero. Displays provisional scores and breakdown statistics for objective assessment sections immediately upon submission confirmation. Enables students to log technical incident reports or dispute automated flags before finalizing their examination submission. |

As detailed in Table X, the mobile application modules are engineered to maintain high examination fidelity despite hardware and connectivity constraints. The on-device Edge AI modules (Face Mesh and YAMNet) process visual and acoustic signals locally without transmitting heavy continuous media streams over cellular networks. Combined with the offline answer buffering engine and operating-system kiosk locks, the mobile application guarantees that student assessments remain resilient, secure, and fully auditable from pre-flight calibration through final submission.
